💡 **What:**
- Added `aria-invalid` and `aria-describedby` attributes to dynamic inputs in `Login.jsx` and `Signup.jsx`.
- Connected error messages to input fields via unique IDs (e.g., `id="email-error"`).
- Added `required` attributes to essential inputs.
- Enhanced `PasswordProtected` component in `App.jsx` with `onKeyDown` 'Enter' submission support and `aria-label` attributes.

🎯 **Why:**
- To improve accessibility and provide native semantic feedback to screen reader users regarding invalid inputs.
- Form elements now explicitely link their error states to descriptive spans, improving user guidance.
- Submitting via the "Enter" key on password prompts is a standard and highly expected interaction that was previously missing.

♿ **Accessibility:**
- Ensures screen readers announce exactly why an input is invalid by relating the input to its corresponding error message element.
- Makes the generic "Submit" button clearer with `aria-label`.
